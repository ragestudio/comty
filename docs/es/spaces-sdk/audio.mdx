El módulo de audio tiene dos gestores independientes:

- `audioManager` enruta la reproducción y la captura entre los dispositivos disponibles (altavoz, auricular, bluetooth, headsets) y expone la lista de dispositivos.
- `audioProcessing` es dueño de las preferencias de procesado del micrófono (supresión de ruido, ganancia, puerta, cancelación de eco) y las persiste a través del adaptador.

```ts
import { audioManager, useAudioStore } from "@comty/spaces-sdk/rtc/audio"
import {
	audioProcessing,
	useAudioProcessing,
} from "@comty/spaces-sdk/rtc/audio/processing"
```

Ambos gestores dependen del adaptador. Sin `registerAudioRouting` / `registerAudioDevicesEvents` la lista de dispositivos se queda vacía y los métodos devuelven `false`; sin `registerAudioProcessing` el SDK lo reporta como no disponible.

## Dispositivos de audio

### Estado

| Campo | Tipo | Descripción |
| --- | --- | --- |
| `devices` | `AudioDevice[]` | Dispositivos de entrada y salida |
| `outputDeviceId` | `string \| null` | Salida seleccionada |
| `inputDeviceId` | `string \| null` | Entrada seleccionada |
| `speakerEnabled` | `boolean` | Estado del altavoz (nativo) |
| `speakerAvailable` | `boolean` | Si el runtime tiene altavoz |
| `routeMode` | `AudioRouteMode` | `"call"` o `"high-fidelity"` |
| `routeModeSupported` | `boolean` | Si el runtime soporta modos de ruta |

```ts
interface AudioDevice {
	id: string
	kind: "input" | "output"
	type: string
	label: string
	isCurrent: boolean
}
```

### Getters

| Getter | Tipo | Descripción |
| --- | --- | --- |
| `strategy` | `AudioStrategy \| null` | Primera estrategia soportada |
| `outputs` | `AudioDevice[]` | Dispositivos de salida |
| `inputs` | `AudioDevice[]` | Dispositivos de entrada |
| `selectedOutput` | `AudioDevice \| null` | Salida actual |
| `selectedOutputIsBluetooth` | `boolean` | - |
| `hasBluetoothHeadset` | `boolean` | - |

El helper `isBluetoothDevice(device)` se exporta para las UIs que necesiten mostrar los controles específicos de bluetooth.

### Métodos

| Método | Firma | Descripción |
| --- | --- | --- |
| `observe` | `() => () => void` | Escucha eventos de hotplug, devuelve la función para cancelar. Llamar una vez al arrancar |
| `setActive` | `(active: boolean) => Promise<void>` | Indica que empezó/terminó una llamada. Mientras está inactivo no se retiene ninguna ruta; al empezar se prefiere bluetooth automáticamente |
| `refresh` | `() => Promise<AudioDevice[]>` | Vuelve a enumerar dispositivos y refresca el estado |
| `restore` | `() => Promise<void>` | Restaura la selección persistida de entrada/salida |
| `setSpeakerEnabled` | `(enabled: boolean) => Promise<void>` | Altavoz on/off |
| `toggleSpeaker` | `() => Promise<void>` | Alterna el altavoz |
| `setOutputDevice` | `(deviceId: string) => Promise<boolean>` | Enruta la reproducción y persiste la selección |
| `setInputDevice` | `(deviceId: string) => Promise<boolean>` | Selecciona el dispositivo de captura y persiste la selección |
| `setRouteMode` | `(mode: AudioRouteMode) => Promise<boolean>` | Solo tiene sentido con salida bluetooth |
| `handleDevicesChanged` | `() => Promise<void>` | Maneja una ráfaga de hotplug, lo llama `observe` |

```tsx
function DevicePicker() {
	const { outputs, outputDeviceId } = useAudioStore()
	const { setOutputDevice } = audioManager

	return (
		<select
			value={outputDeviceId ?? ""}
			onChange={(event) => setOutputDevice(event.target.value)}
		>
			{outputs.map((device) => (
				<option
					key={device.id}
					value={device.id}
				>
					{device.label}
				</option>
			))}
		</select>
	)
}
```

### Modos de ruta

| Modo | Comportamiento |
| --- | --- |
| `call` | Ruta de voz del sistema: micrófono y salida del headset bluetooth |
| `high-fidelity` | La salida bluetooth se queda en A2DP estéreo y la captura usa el micrófono integrado |

Seleccionar una salida bluetooth cambia a `call`. Seleccionar una salida no bluetooth también fuerza `call`. Cambiar a `high-fidelity` mueve la entrada al micrófono integrado.

### Estrategias

Una `AudioStrategy` describe cómo un runtime enumera y enruta el audio. El gestor elige la primera estrategia cuyo `supports()` devuelve `true`:

1. `native-audio-routing` - envuelve el `AudioRouting` del adaptador (React Native, y también web/electron, que registran su implementación del navegador).
2. `web-media-devices` - fallback que solo enumera dispositivos con `navigator.mediaDevices`, usado cuando no hay adaptador de rutas registrado.

```ts
interface AudioStrategy {
	name: string
	speakerAvailable: boolean
	supports(): boolean
	getDevices(): Promise<AudioDevice[]>
	setSpeakerEnabled?(enabled: boolean): Promise<void>
	isSpeakerEnabled?(): Promise<boolean>
	setOutputDevice?(deviceId: string): Promise<boolean>
	setInputDevice?(deviceId: string): Promise<boolean>
	setRouteMode?(mode: AudioRouteMode): Promise<boolean>
	isBluetoothAvailable?(): Promise<boolean>
	resetRouting?(): Promise<boolean>
}
```

## Procesado del micrófono

### Estado

| Campo | Tipo | Descripción |
| --- | --- | --- |
| `available` | `boolean` | Hay un adaptador registrado |
| `capabilities` | `AudioProcessingCapabilities \| null` | Qué soporta el host |
| `input` | `AudioInputProcessingConfig` | Configuración actual de entrada |
| `output` | `AudioOutputProcessingConfig` | Configuración actual de salida |

### Configuración

```ts
type NoiseSuppressionMode = "off" | "system" | "rnnoise"
type InputGainMode = "manual" | "auto"

interface AudioInputProcessingConfig {
	noiseSuppression: NoiseSuppressionMode
	gateEnabled: boolean
	gateThresholdDb: number
	gainMode: InputGainMode
	gainDb: number
	echoCancellation: boolean
}

interface AudioOutputProcessingConfig {
	gainDb: number
}

interface AudioProcessingCapabilities {
	noiseSuppression: NoiseSuppressionMode[]
	gate: boolean
	manualGain: boolean
	autoGain: boolean
	echoCancellation: boolean
	outputGain: boolean
}
```

Rangos: ganancia `-10` a `20` dB, umbral de puerta `-80` a `0` dB. Valores por defecto:

```ts
{
	input: {
		noiseSuppression: "system",
		gateEnabled: false,
		gateThresholdDb: -50,
		gainMode: "manual",
		gainDb: 0,
		echoCancellation: true,
	},
	output: { gainDb: 0 },
}
```

### Métodos

| Método | Firma | Descripción |
| --- | --- | --- |
| `sync` | `() => void` | Publica disponibilidad/capacidades y carga una vez la configuración persistida. Llamar tras registrar el adaptador |
| `apply` | `() => Promise<void>` | Vuelve a aplicar la configuración actual |
| `update` | `(input?, output?) => Promise<void>` | Fusiona una configuración parcial, la limita, la persiste y la aplica |
| `setNoiseSuppression` | `(mode) => Promise<void>` | - |
| `setGateEnabled` | `(enabled: boolean) => Promise<void>` | - |
| `setGateThresholdDb` | `(db: number) => Promise<void>` | - |
| `setGainMode` | `(mode: InputGainMode) => Promise<void>` | - |
| `setInputGainDb` | `(db: number) => Promise<void>` | - |
| `setEchoCancellation` | `(enabled: boolean) => Promise<void>` | - |
| `setOutputGainDb` | `(db: number) => Promise<void>` | - |

```ts
await audioProcessing.setNoiseSuppression("rnnoise")
await audioProcessing.update({ gateEnabled: true, gateThresholdDb: -45 })
```

Cada cambio se escribe en el almacenamiento del adaptador y se aplica al instante, también con una llamada en curso.

### Requisitos del adaptador

```ts
interface AudioProcessingAdapter {
	capabilities: AudioProcessingCapabilities
	apply(config: AudioProcessingConfig): Promise<void>
	// opcional: constraints que se mezclan en getUserMedia para el micrófono
	getMicrophoneConstraints?(): MediaTrackConstraints
}
```

La implementación web (registrada por `initializeRtcAdapter`) aplica la configuración al grafo de audio que crea el hook `registerMediaStreamProcessor` (rnnoise, ganancia y puerta). En React Native la aplica el host con su propio módulo nativo.

## Claves persistidas

Los ajustes se guardan con `adapter.audioSettings`:

```ts
import {
	AUDIO_SETTINGS_KEYS,
	readAudioSetting,
	writeAudioSetting,
} from "@comty/spaces-sdk/rtc/audio/settings.js"

AUDIO_SETTINGS_KEYS
// audio:noiseSuppression
// audio:echoCancellation
// audio:gainMode
// audio:gateEnabled
// audio:gateThresholdDb
// audio:inputGainDb
// audio:outputGainDb
// audio:inputDeviceId
// audio:outputDeviceId
```

## Ejemplo de ciclo de vida

```ts
// arranque: registra el adaptador y luego
audioManager.observe()
audioProcessing.sync()

// al entrar en un canal de voz
await audioManager.setActive(true)
await audioManager.restore()

// al salir
await audioManager.setActive(false)
```

El helper web `initializeRtcAdapter()` ya llama a `audioManager.observe()` y `audioProcessing.sync()`; en React Native los llama el host explícitamente.
