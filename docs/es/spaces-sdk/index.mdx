`@comty/spaces-sdk` es el SDK cliente agnóstico de **Comty Spaces**: grupos, canales, chat, RTC de voz/vídeo (sobre un SFU mediasoup) y toda la fontanería específica de plataforma (rutas de audio, procesado de audio, captura de pantalla, persistencia) que cada aplicación host aporta a través de un adaptador.

El SDK no depende de React ni de ningún kit de UI. El estado vive en stores de zustand con suscripciones vanilla y los hooks de React se exportan como una capa fina de conveniencia. Por eso el mismo paquete alimenta tanto la app web / electron (`packages/app`) como la app React Native (`packages/native`).

## Requisitos

- Un servidor Comty con el servicio `rtc` y un SFU accesible.
- `comty.js` configurado con una sesión autenticada y su conexión websocket `"main"` abierta. El SDK lee el token y el id de usuario de la sesión y reutiliza el socket principal para todos los eventos de Spaces.
- Globales WebRTC compatibles con `mediasoup-client` en el runtime. En React Native los aporta `@ragestudio/react-native-webrtc`; en web son los del navegador.

## Instalación

```bash
pnpm add @comty/spaces-sdk
```

El paquete distribuye fuentes TypeScript y expone un mapa `exports`, por lo que están disponibles tanto el barrel como las rutas individuales. Las rutas explícitas (`chat/types`, `db/react`, `rtc/web`, ...) funcionan tal cual; las rutas profundas resueltas por el comodín (`rtc/self/constants`, `chat/adapters`, ...) deben incluir la extensión `.js`:

```ts
import { SCREEN_RESOLUTIONS } from "@comty/spaces-sdk/rtc/self/constants.js"
import { groupAdapter } from "@comty/spaces-sdk/chat/adapters.js"
```

## Arquitectura

| Capa | Responsabilidad |
| --- | --- |
| `adapter` | Primitivas de plataforma registradas por el host: globales WebRTC, getter de sesión, rutas y dispositivos de audio, procesado de audio, volumen por track, procesadores de stream, audio de sistema, soundpad, ajustes de audio y logging |
| `db` | Caché offline sobre tinybase (grupos, canales, miembros, mensajes, usuarios) con persister de IndexedDB para web |
| `group` | Store del grupo activo: metadatos, canales, miembros, presencia, decoraciones y el estado de voz de cada canal |
| `groupsList` | Lista de membresías del usuario |
| `users` | Caché compartida de perfiles (memoria + base de datos + API) usada por miembros, mensajes y tiles de voz |
| `chat` | Sesión de chat activa (canal de grupo o DM) con paginación, envío optimista, typing y sincronización |
| `rtc` | Sesión de voz/vídeo: dispositivo mediasoup, transports de envío/recepción, medios locales, producers y consumers remotos, detección de voz y bus de eventos |
| `rtc/audio` | Rutas de dispositivos (`audioManager`) y preferencias de procesado del micrófono (`audioProcessing`) |

Solo hay un grupo y una sesión de chat activos a la vez. Ambos stores son singletons y exponen un objeto `actions`; `init()` reemplaza la sesión anterior y `reset()` la limpia. Cada acción asíncrona lleva un contador de generación, de modo que la respuesta de una sesión anterior nunca puede sobrescribir el estado actual. El store de `users` no está ligado a una sesión: sobrevive a la navegación y solo se limpia con `resetUsers()`.

## Arranque

El orden importa: el adaptador debe registrarse antes de capturar o reproducir cualquier medio, y el socket debe estar conectado antes de inicializar el servicio RTC.

```ts
import client from "comty.js/client"
import { authManager } from "comty.js"

import { rtcService } from "@comty/spaces-sdk/rtc"
import { initializeRtcAdapter } from "@comty/spaces-sdk/rtc/web"
import { startWebPersistence } from "@comty/spaces-sdk/db/persister-web"

// 1. sesión + autenticación
await authManager.start()

// 2. caché offline
await startWebPersistence()

// 3. adaptador de plataforma (web / electron)
await initializeRtcAdapter()

// 4. socket de tiempo real
await client.ws.connect("main")

// 5. servicio rtc, enlaza los eventos "media:*" del socket
await rtcService.initialize()
```

En React Native el adaptador se registra manualmente en lugar de llamar a `initializeRtcAdapter()`. Ver [Adapter](adapter).

## Uso mínimo

```tsx
import { useEffect } from "react"
import {
	GroupStore,
	useGroupChannels,
	useGroupData,
} from "@comty/spaces-sdk/group"
import { subscribeGroupSocket } from "@comty/spaces-sdk/events"
import { rtcService, useRTCStore } from "@comty/spaces-sdk/rtc"

function GroupScreen({ groupId }: { groupId: string }) {
	const group = useGroupData()
	const channels = useGroupChannels()
	const channel = useRTCStore((state) => state.channel)

	useEffect(() => {
		const actions = GroupStore.getState().actions
		const unsubscribe = subscribeGroupSocket(groupId)

		actions.init(groupId)

		return () => {
			unsubscribe()
			actions.reset()
		}
	}, [groupId])

	const join = (channelId: string) =>
		rtcService.handlers.joinChannel({ groupId, channelId })

	return (
		<div>
			<h1>{group?.name}</h1>
			<p>Conectado a: {channel?.name ?? "ninguno"}</p>
			{channels.items.map((item) => (
				<button
					key={item._id}
					onClick={() => join(item._id)}
				>
					{item.name}
				</button>
			))}
		</div>
	)
}
```

## Stores y acciones

Cada store es un store de zustand con API vanilla, así que también se puede usar fuera de React:

```ts
import { GroupStore } from "@comty/spaces-sdk/group"
import { ChatStore } from "@comty/spaces-sdk/chat"
import { ensureUsers } from "@comty/spaces-sdk/users"
import { rtcService } from "@comty/spaces-sdk/rtc"

await GroupStore.getState().actions.init(groupId)
await ChatStore.getState().actions.send({ message: "hola" })
await ensureUsers(["user_1", "user_2"])

rtcService.self.toggleMute()
```

- `store.getState()` devuelve el estado actual junto con el objeto `actions`.
- `store.setState(...)` muta el store (no lo uses fuera del SDK).
- `store.subscribe(listener)` es la suscripción vanilla de zustand.
- Los hooks de React se exportan por porción (`useGroupData`, `useChatTimeline`, `useRTCStore`, ...).

## Helpers y clases

| Export | Descripción |
| --- | --- |
| `BaseStore<State>` | Wrapper de store vanilla de zustand usado por el SDK; expone `getState`, `setState` y `useStore(selector?)` (`@comty/spaces-sdk/classes`) |
| `BaseActions` | Clase base para grupos de acciones; expone `state`, `store`, `setState` y `getState` (`@comty/spaces-sdk/classes/BaseActions.js`) |
| `IndexedArray<T>` | Array con helpers `insert`, `delete` y `clear` (`@comty/spaces-sdk/classes/IndexedArray.js`) |
| `MirrorMap<K, V>` | Vista de solo lectura sobre un `Map` externo (`@comty/spaces-sdk/classes/MirrorMap.js`) |
| `version` | Versión del SDK tomada de `package.json` |

## Logging

Todos los módulos usan `@comty/shared/utils/logger` y derivan loggers hijos (`rtc-core`, `self`, `clients`, `consumers`, `transports`, `voice-detection`, `audio-manager`, ...). El host puede redirigirlos:

```ts
import { adapter } from "@comty/spaces-sdk"

adapter.registerLogLevel("info")

// sirve cualquier objeto con la interfaz de console
adapter.registerLogger({
	log: (...args) => myReporter.debug(...args),
	debug: (...args) => myReporter.debug(...args),
	info: (...args) => myReporter.info(...args),
	warn: (...args) => myReporter.warn(...args),
	error: (...args) => myReporter.error(...args),
})
```
